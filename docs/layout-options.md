## 一、查到嘅硬資料

**10-foot UI（電視距離）**
- 1080p 電視上，正文最少 34–36px；次要標籤唔可以細過 ~24px（UI/UX Atlas）
- 安全區 = 四邊各 5% inset，避免 overscan 食字
- 電視距離冇 hover、冇 cursor，狀態只可以靠 focus 表達
- Lean-back：資訊密度要比任何其他平台低

**Jackbox（派對遊戲分工）**
- 共享大屏只放「公開資訊」，每人手機只放「私人／操作」資訊
- 房間 code 入場，唔使裝 app
- 主持／玩家嘅注意力被刻意分開：眼望大屏，手喺手機

**iPad 版面**
- Split View 下闊度可以窄到 320 / 375 / 507 / 678，必須有窄版
- iPad 直度 744–834、橫度 1024–1194，兩者係兩個唔同設計問題，唔係同一個版面拉闊

**我哋嘅實際使用場景（由你之前講嘅歸納）**
- 一個主持，自己一個人操作
- 一部 iPad 做主持機，可能 AirPlay／HDMI 去電視或投影
- 一隊 4–8 人，通常 2–4 隊
- 現場有其他人望住同一個畫面

## 二、五個真正唔同嘅版面方案

### A. Stage + Console Rail（三欄控制台）
- **結構**：橫度 iPad 分三欄 —— 左 20% 隊伍分數（常駐、live）、中 55% 題目 stage + 倒數、右 25% 主持操作（對／跳過／撤銷／回合資訊）
- **直度**：塌成「stage 上、操作欄下」，分數變頂部細條
- **主持動線**：右手永遠喺右欄，唔使追住按鈕位置；眼睛喺中間
- **觀眾**：中間永遠係題目，唔會被 UI 搶
- **成本**：中（CSS grid 三欄 + 兩個斷點）
- **風險**：橫度 1024 闊時右欄得 ~250px，判定鍵要夠大就要壓縮 stage

### B. Scoreboard-first（龍門陣／遊戲節目看板）
- **結構**：成個畫面就係分數板 —— 每隊一格大字（4–8 隊都排得落），題目以「now playing」橫幅浮喺上面；判定時分數格會跳動
- **直度**：2 欄 × N 行隊伍格，題目橫幅置頂
- **主持動線**：判定鍵做成底部一大條（左跳過、右對），或每隊格旁邊一個小 ✓
- **觀眾**：似《獎門人》現場看板，氣氛最強，特別係多隊比賽
- **成本**：中高（要重寫分數板做主角，題目退居橫幅）
- **風險**：1–2 隊時畫面好空；題目唔夠大（同「一人背向屏幕」需求衝突）

### C. Card Deck（卡牌堆、手勢判定）
- **結構**：題目係一張卡，下面露出下一張；判定 = 掃右（對）／掃左（跳過），或者點畫面左右半邊
- **直度**：卡牌佔 70% 高，底部一條細分數帶
- **主持動線**：單手拇指，唔使瞄準細掣；掃嘅方向同結果有物理感
- **觀眾**：卡片翻頁動畫好睇，但題目會「移動」，遠距離閱讀差少少
- **成本**：中（Pointer Events + 過場動畫）
- **風險**：手勢誤觸；長者／小朋友主持唔慣 swipe；冇「撤銷」就要靠 shake

### D. Two-surface（iPad 做控制器，電視做大屏）
- **結構**：iPad 只顯示主持專用：大判定鍵、倒數、下一題預覽、隊伍分數；電視／投影顯示公開畫面：題目大字、分數板、倒數
- **直度**：iPad 直度最順（一隻手拎住）
- **主持動線**：最好 —— 主持可以望住人，唔使望住部機；按鈕可以做到半個畫面大
- **觀眾**：題目喺電視上最大化，冇 UI 雜訊
- **成本**：高（要兩個 surface 同步：WebSocket/SSE，或同一部機開兩個視窗用 BroadcastChannel）
- **風險**：要第二塊屏；現場網絡；多一個 failure mode

### E. Focus-first（電視 App 式，遙控／鍵盤驅動）
- **結構**：全部變成大格 focusable tile，方向鍵／D-pad 移動，Enter 確認；冇 hover、冇細掣
- **適用**：iPad 鏡像去電視、用藍牙遙控或鍵盤操作；或者想完全唔使睇住部機
- **成本**：中（focus 管理 + roving tabindex）
- **風險**：主持要學；比觸控慢

## 三、對照（按我哋嘅場景評分，5 分最好）

- 主持單手操作：D 5 · C 5 · A 4 · B 3 · E 2
- 遠距離可讀（投影）：D 5 · A 4 · B 3 · C 3 · E 4
- 多隊（4–8）氣氛：B 5 · A 4 · D 3 · C 3 · E 3
- 實作成本（越低越好）：A 4 · C 3 · B 3 · E 3 · D 1
- 離線／單機可用：A 5 · B 5 · C 5 · E 5 · D 2（要同步）

## 四、我嘅建議

**先做 A（三欄控制台）做橫度主持台，直度保持「stage + 底部操作」；之後如果真係落地活動用，再加 D 做「iPad 控制器 + 電視大屏」。**

理由：
- A 係純前端改動，一次過解決「橫度 iPad 只係拉闊」呢個核心批評，而且即刻改善主持手部動線
- B 睇落最似遊戲節目，但同「一人背向屏幕猜」衝突：題目要最大，分數係次要
- C 好 touch-native，但 swipe 判定喺真人派對容易誤觸，而且題目移動影響遠讀
- D 係最正確嘅長期答案（Jackbox 已經證明），但要加同步層，唔應該同版面改動一次過做

## 五、等你決定嘅三條

1. 你部 iPad 係**淨係自己做屏**，定係會**鏡像／接線去電視**？（決定要唔要行 D）
2. 一場比賽通常幾多隊？1–2 隊（A 夠）定 4 隊以上（B 值得考慮）
3. 主持係**坐定**定**行嚟行去**？（行嚟行去 → 單手 + 大掣 + D 方案優先）
