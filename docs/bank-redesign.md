# 題庫重新設計（2026-10-31）

> ✅ 已實作方案 B（commit `d5b9dcd`）

## 一、現況量度

| 項目 | 實測 |
|---|---|
| 版面 | **一個 1048×646 textarea** 裝全部題目（62 題 = 68 行） |
| 結構 | 只有 `# 類別名` 一行做分隔；類別冇獨立實體 |
| 操作 | 只有「打字」同「重新載入」；冇搜尋、冇去重、冇改類別、冇刪類別 |
| Tab | 題目庫（原文）／組合（揀題）——兩個 tab 語意唔同層 |
| 存檔 | 打字 400ms debounce 整份 `PUT`；冇 undo，只有 3 份後台快照 |
| 資料模型 | `sets` 用**題目文字**做 key（`items.includes(it.t)`）→ **改一個字，組合就斷** |

## 二、核心問題

1. **冇「題目」實體**：題目只是文字行，冇 id、冇類別屬性、冇 per-item 操作
2. **改一題要喺 68 行裡搵**：冇搜尋、冇篩選
3. **類別不可操作**：改類別名、刪類別、搬題目去另一個類別，全部要人手選取文字
4. **批量輸入係唯一強項**：貼 100 題一次過，反而係現時最順嘅操作

## 三、三個方案

### A · 左類別欄 + 右題目表（Airtable／Anki 式）
```
┌ 類別 ────┬ 題目 ────────────────────────┐
│ 全部 62  │ 🔍 搜尋            ＋ 新增題目 │
│ 港式小食 12│ 1 雞蛋仔              ×      │
│ 香港地標 10│ 2 菠蘿包              ×      │
│ 日常動作 12│ 3 絲襪奶茶            ×      │
└──────────┴──────────────────────────────┘
```
- 點類別 → 右邊只顯示該類，62 題分 6 類後每屏 10 行左右
- 類別有自己嘅操作：改名、刪除、排序
- 行內編輯、Enter 加下一行、× 刪
- **代價**：多一層導航；「全部」視圖仍然長

### B · 單一表格 + 類別行內下拉 + 批次工具（推薦）
```
🔍 搜尋   [全部類別 ▾]   62 題   [批次貼上] [去重]
┌────────────────────────────────────────────┐
│ 1 │ 雞蛋仔        │ 港式小食 ▾ │ ×         │
│ 2 │ 菠蘿包        │ 港式小食 ▾ │ ×         │
│ 3 │ 絲襪奶茶      │ 港式小食 ▾ │ ×         │
└────────────────────────────────────────────┘
```
- 每行三個可操作位：題目、類別（下拉，可以即場搬）、刪除
- 頂帶：搜尋、類別篩選、題數、批次貼上（彈 sheet：貼多行 → 揀類別 → 一次加入）、去重
- **保留你最順嘅批量貼上**，但唔再係「全份文件」
- 類別自動由題目歸納，唔使另外管

### C · 保留全文 textarea，加結構側欄（改動最細）
- textarea 照舊；左邊加類別目錄（點 → scroll 到該類並高亮）；頂加搜尋／去重／統計
- **好處**：打字同貼上仍然最快
- **壞處**：仍然係「文件」感，冇 per-item 操作，你上次就係嫌呢個

## 四、無論揀邊個都要修嘅底層問題

1. **題目要有 id**：`sets` 由「存文字」改成「存 item id」，改字唔會斷組合
2. **要 undo**：現時 3 份快照冇 UI，誤刪冇得返；加「還原上一版」
3. **要搜尋**：68 行冇搜尋等於冇得改

## 五、建議

**B**。理由：
- 你上次接受「表格路線」但嫌唔夠用，因為當時類別只係 tab（睇得，唔改得）
- B 把類別變成**行內下拉**，可以即場搬題，唔使返去改 `#` 行
- 批量貼上保留（彈 sheet），你一次貼 100 題嘅流程唔變
- 一屏 20+ 行，62 題兩屏睇完，比 646px 高嘅 textarea 更易掃
