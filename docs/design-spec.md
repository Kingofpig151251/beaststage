# 大電視 · 產品設計規格（v1，未實作）

> 目的：停止「逐句 feedback 改版面」。所有 UI 改動要先對得住呢份 spec，唔對就唔改。
> 一句話定位：**一個人坐喺 iPad 前面主持派對猜題，其他人望住同一個畫面。**
> 所以呢個產品有兩種畫面，而且只可以有兩種：**主持畫面**同**工具畫面**。

---

## 一、三個語氣決定（決定所有視覺取捨）

1. **主持畫面＝舞台，唔係 dashboard**
   一個時間只有一件事：個字。其餘（分數、時鐘、掣）壓到邊緣。密度要**極低**。
2. **工具畫面＝紙，唔係舞台**
   改題、睇榜係「維護」行為，唔需要氣氛。密度要**高**，裝飾要**零**。
3. **兩種畫面共用同一套 token，但唔共用同一個密度**
   呢個就係之前散咗嘅原因：我試過用舞台語言去做工具頁（大色塊、panel），又試過用工具語言做主持頁（三欄、rail）。

---

## 二、色彩角色（每個顏色只有一個工作）

| Token | 值 | 唯一用途 | 唔准用嚟 |
|---|---|---|---|
| `--paper` / `--paper-2` / `--paper-3` | 深紫黑三層 | 底 / 卡 / 卡上卡 | 做裝飾漸層 |
| `--ink` / `--ink-2` / `--muted` | 白三階 | 主要文字 / 次要文字 / 標籤 | 用 muted 做正文 |
| `--rule` | 暗紫灰 | 分隔線、邊框 | 做陰影 |
| `--accent`（ember 橙） | oklch 66% | **當前動作**：對、當前隊、冠軍 | 做背景大色塊（題庫頁已犯過） |
| `--accent-2`（acid 綠） | oklch 88% | **時間同成功**：時鐘、進度條、已同步 | 做按鈕主色 |
| `--focus` | acid 綠 | 鍵盤 focus 環 | 做裝飾 |

**規則**：同一畫面最多一個 ember 焦點。有兩個就代表你未決定邊個係主角。

---

## 三、字階（三級，唔准自創）

| 級 | 大小 | 字體 | 用喺 |
|---|---|---|---|
| 舞台字 | `clamp(48px, 22vh, 240px)`，自動填滿 | display 900 | 主持畫面嘅題目 |
| 標題 | `clamp(22px, 3vw, 30px)` | display 900 | 每頁 h1 |
| 正文 | 14–16px | body | 內容、輸入 |
| 標籤 | 11–12.5px | mono 或 body | 狀態、計數、提示 |

**數字一律 mono + tabular**（分數、時鐘、題數）。
**規則**：主持畫面唔准出現細過 14px 嘅字（距離閱讀）；工具畫面唔准出現大過 30px 嘅字（除 h1）。

---

## 四、密度（兩檔，冇中間）

- **主持畫面**：一屏一個視覺重心（題目），其餘最多兩條邊緣帶（上：狀態；下：判定）。
- **工具畫面**：一屏要塞得落 60 題／60 行，行高 34–40px，靠分隔線分組，唔靠卡片。

---

## 五、元件清單（只准用呢啲，唔准為單一畫面自創）

`pill`（狀態）· `tag`（回合／輪到）· `btn-primary`（每頁唯一主動作）· `btn-quiet`（其餘）· `input` / `textarea` · `card`（主持舞台）· `row`（工具清單一行）· `sync-dot`（連線狀態）· `toast`（右下細 pill）

**規則**：新畫面要嘅嘢如果清單冇，先加落呢份 spec，再加落 CSS，最後才用。

---

## 六、資訊架構（4 個畫面，一個入口）

```
主頁（設定）
 ├─ 開始 → 主持台（準備 → 倒數 → 出題 → 判定）
 │            └─ 完場 → 結果（冠軍 + 其餘名次）
 └─ 題庫（工具）· 排行榜（工具）
```

- **主頁**：唯一主動作 = 開始遊戲。左：隊伍名單；右：計時 + 題庫類別。
- **主持台**：唯一主動作 = 對。其餘全部次級。
- **結果**：唯一主動作 = 再玩一次。
- **題庫**：工具頁，唯一主動作 = 打字（自動儲存）。
- **排行榜**：工具頁，唯讀。

---

## 七、三條禁令（用嚟防止再「愈改愈無方向」）

1. **唔准為一個畫面自創版面**：先用 spec 內嘅元件砌，砌唔到就返嚟改 spec。
2. **唔准同時有兩種密度**：舞台頁要大字，工具頁要細字，唔准「一半大一半細」。
3. **唔准用色塊做裝飾**：ember 只代表「當前動作」，唔係主題色。

---

## 八、變更流程

1. 任何 UI 改動 → 先寫一句「呢個改動符合 spec 邊一條」
2. 改完 → 量三個數：溢出（`scrollHeight <= vh`）、主動作位置、字級
3. 一次只改一個畫面，唔准連環改三個

---

## 九、已定案（2026-10-31）

1. **題庫＝工具**：細字、密、冇裝飾；同主持台兩套密度，但共用同一套 token。
2. **出題時完全唔顯示分數**：分數只喺「準備畫面」（每隊交接）出現。理由：出題時唯一主角係個字。
3. **iPad 橫度＝主場景**（放枱、坐定主持）；直度只保證唔爛，唔係設計目標。

### 由此推出嘅主持台規格

```
┌──────────────────────────────────────────────┐
│ 類別 · 剩 N 題                 45 秒  暫停 結束 │  top band（狀態）
│▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔│  3px 進度條（acid）
│                                              │
│                 題目字（撐滿）                 │  舞台（唯一重心）
│                                              │
│▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁│
│  跳過              撤銷                 對     │  bottom band（判定）
└──────────────────────────────────────────────┘
```

- 出題畫面**冇分數、冇隊名 chip、冇規則提示**（提示搬去準備畫面）
- 主持台只有三個掣：**跳過 · 撤銷 · 對**；管理動作只剩「暫停」
- 回合一律由時間到自動結束（每回合最少 5 秒），所以唔需要「結束回合／結束遊戲」
- 準備畫面＝隊名（大）＋ 第 N / M 隊 ＋ 全隊分數（細行）＋ 開始
- 主持台只有一個 ember 焦點：**對**
- 每次只改一個畫面：主持台 → 結果 → 主頁 → 題庫
